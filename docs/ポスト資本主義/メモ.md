# ポスト資本主義 実験仕様ドラフト

## 0. 位置づけ（スコープ）

この実験のゴールは「AGI時代の若者感情の再現」ではなく、**価値システムの違いが人間の豊かさ指標に与える影響比較**である。  
したがって、年齢層や国設定は差し替え可能な実験パラメータとして扱い、特定ドメイン（例: AGI若者）へ固定しない。

## 1. 実験の問い

「資本主義に代わる価値システムとして、何が人間の豊かさを最も高めるか？」

## 2. 実験環境

- **場所**: 鎌倉をモデルにした2D仮想空間
- **エリア**: 海岸 / お寺 / アトリエ / 森 / 縁側カフェ
- **行動**: エージェントはエリア間を移動し、同じエリアにいる他者と会話できる
- **登場人物**: AIエージェント6人
- **期間**: 30日間（1ステップ = 1日）
- **移動ルール（暫定）**: 各日、各エージェントは0〜1回エリア移動できる（同一エリアへの複数滞在を許可）
- **初期配置（暫定）**: Day1時点で6人を5エリアへランダム配置（seed固定）
- **会話ルール（暫定）**: 同一エリアに2人以上いる場合、当日中に会話イベントが発生する

## 3. 共通前提（全世界共通）

以下はすべての世界で固定する。

- 衣食住保障
- 時間自由
- 強制なし
- 情報平等
- 出発点の平等

## 5. 価値システムの発動設計（命令なし）

### 5.1 基本方針

各世界でLLMエージェントに「この価値観で行動せよ」と命令するのではなく、以下を前提情報として与える。

- **制度設計**: 何が評価・承認されるか（例: 収益、貢献、ケア）
- **資源循環**: 交換、共有、贈与、協働のどれが成立しやすいか
- **社会規範**: 会話で好意的に受け止められる語り方・行動傾向
- **可視化指標**: エージェントが日々目にする社会状態のダッシュボード項目

価値システムは「命令」ではなく「環境と意味づけ」として埋め込む。

### 5.2 価値システムごとの前提情報テンプレート

| 世界ID | 価値システム | 主に与える前提情報（命令ではない） |
|---|---|---|
| W01 | 資本主義 | 価格シグナル、成果報酬、競争機会、個人最適の可視化 |
| W02 | ギフト経済 | 贈与履歴、返礼期待の緩さ、評判としての信頼蓄積 |
| W03 | コモンズ | 共有資源残量、共同管理ルール、フリーライド検知の社会的視線 |
| W05 | 自律分散 | 中央指令不在、ローカル合意の意思決定、分散調整コスト |
| W06 | ケアエコノミー | ケア需要、ケア提供の社会的承認、ケア疲労の蓄積指標 |
| W07 | 相互扶助 | 助け合いネットワーク密度、困窮者への即応規範、互恵記憶 |
| W09 | 自分らしさ | 役割拘束の低さ、自己選択機会、内的一貫性の重視 |
| W10 | 精神性の成熟 | 内省時間、衝動抑制、意味づけの深さ、対立時の省察規範 |
| W11 | 遊び | 試行錯誤の許容、失敗コストの低さ、創発的協働の機会 |
| W14 | 日本的価値観 | 和・間合い・場の空気、相互配慮、関係維持の暗黙規範 |
| W16 | 何も指定しない（対照群） | 最小限の物理条件のみ。価値誘導情報は与えない |

### 5.3 プロンプト実装の分離

1. **共通レイヤー（全世界同一）**  
   観測器としての役割、出力JSON形式、自己申告6項目、会話ログ形式

2. **世界コンテキスト（世界ごとに差し替え）**  
   制度・資源循環・社会規範・可視化指標のみ差し替える

3. **日次状態入力（全世界同型）**  
   エリア、同居者、当日イベント、前日記憶、自己状態

この分離により、「命令文の強さ」ではなく「環境条件の差」で比較できる。

### 5.4 命令なし運用での妥当性チェック

- 世界ごとの会話内容に、対応する価値語彙が自然出現しているかを確認
- 価値語彙の出現比率と行動カテゴリ分布が世界ごとに分岐しているかを確認
- W16（対照群）で特定価値への偏りが小さいかを確認

### 5.5 世界コンテキスト文（固定テンプレ草案）

各ステップで `world_context` として渡す短文テンプレート。  
行動命令は含めず、制度・資源循環・社会規範の説明に限定する。

| 世界ID | world_context（草案） |
|---|---|
| W01 | この社会では成果と価格が意思決定の中心で、個人の競争力と交換価値が日々の評価に強く反映される。 |
| W02 | この社会では贈与と返礼が緩やかな信頼で循環し、見返りより関係維持と善意の連鎖が評価されやすい。 |
| W03 | この社会では共有資源を住民が共同管理し、利用と保全の均衡、フリーライド抑制への配慮が重視される。 |
| W05 | この社会では中央命令より自律的な局所判断が尊重され、合意形成は分散的で調整責任が参加者に分配される。 |
| W06 | この社会ではケア労働の価値が可視化され、弱者支援・関係修復・持続可能な配慮行動が高く承認される。 |
| W07 | この社会では困りごとへの相互扶助が規範化され、助けた記憶と助けられた記憶が次の協力を後押しする。 |
| W09 | この社会では外的同調より自己選択の整合性が尊重され、本人の納得感と内的一貫性が評価基準になりやすい。 |
| W10 | この社会では短期利得より内省と意味づけが重んじられ、衝動反応より成熟した受け止め方が期待される。 |
| W11 | この社会では遊びと試行錯誤が正当な活動として扱われ、失敗は罰より学習機会として解釈されやすい。 |
| W14 | この社会では和と場の空気、相互配慮が重視され、関係維持に資する控えめな調整行動が支持されやすい。 |
| W16 | この社会では特定の価値誘導を置かず、最低限の生活保障条件のみが共有され、意味づけは個人差に委ねられる。 |

実装上は、上記短文に加えて当日の状態入力（場所、同居者、イベント、前日記憶）を連結して投入する。

### 5.6 データ管理方針（TSV推奨）

実験条件を再利用・差し替えしやすくするため、以下はTSVで外出しする。

| ファイル名（例） | 用途 | 最低限の列 |
|---|---|---|
| `value_systems.tsv` | 世界IDと価値システムの対応 | `world_id`, `value_system_name`, `is_control` |
| `world_context_templates.tsv` | 各世界の固定コンテキスト文 | `world_id`, `world_context` |
| `agents.tsv` | 実験対象ペルソナ（年齢層は可変） | `agent_id`, `persona`, `age_band`, `base_traits` |
| `places.tsv` | 場所定義 | `place_id`, `place_name`, `description` |
| `interaction_rules.tsv` | 会話・移動の環境条件 | `rule_id`, `condition`, `effect` |
| `daily_observation_schema.tsv` | 日次自己申告と補助指標の定義 | `metric_id`, `metric_name`, `scale`, `description` |

JSON/YAMLに比べてTSVは比較編集・差分レビュー・集計連携が容易なため、試行回数を増やす実験運用に向く。

## 6. 計測指標

毎日、各エージェントが以下6項目を **1〜10** で自己申告する。

- 気分
- 幸福感
- 自分らしさ
- 意味
- 自律性
- 活力

### 6.1 集約指標

- **HFI（Human Flourishing Index）** を各世界で算出
- 定義（現時点）:
  - 1エージェント1日のHFI = 上記6項目の単純平均
  - 世界HFI = 全エージェント・全日程の平均

## 7. 比較の目的

価値システムごとに世界HFIを比較し、30日間の条件下で相対的に人間的豊かさが高まる構造を同定する。  
対象集団（若者中心/多世代/地域別）は差し替え可能とし、同一設計で横展開できることを要件とする。

## 8. 未定義・要決定項目（次に詰める点）

- 各価値システムの前提情報を、実行用プロンプトへどう実装するか（文面・長さ・固定語彙）
- ランダム性の扱い（seed固定の有無、複数試行回数）
- 初期状態の定義（初期感情、関係性、所持資源の有無）
- 日次自己申告の実装方法（自由記述か、定型回答か）
- 異常値や欠測値の処理ルール
- HFI以外の補助指標（分散、不平等度、関係密度など）の採用有無
- 会話イベントの詳細（発話回数上限、1対1/複数人、会話内容の状態反映）

## 9. 汎用化後の実行例（pack指定）

以下は、特定ドメインに依存しない実行例。`--pack` に差し替え対象を渡す。

```bash
# 例: ISSドメインで閉ループ実行
venv/bin/python scripts/run_closed_loop_llm_demo.py \
  --pack domain_packs/iss_benevolence \
  --scenario baseline \
  --start-step 1 \
  --steps 30 \
  --model sonnet
```

```bash
# 国レイヤーのみを単体実行
venv/bin/python scripts/run_country_llm_demo.py \
  --pack domain_packs/iss_benevolence \
  --scenario baseline \
  --start-step 1 \
  --steps 10
```

```bash
# 組織レイヤーのみを単体実行
venv/bin/python scripts/run_organization_llm_demo.py \
  --pack domain_packs/iss_benevolence \
  --scenario baseline \
  --start-step 1 \
  --steps 10
```

補足:
- `--pack` で必要データ（agents/events/time_schedule等）を解決できない場合は、該当TSVを個別引数で明示する。
- `--scenario` 省略時は、packの基本設定のみで実行する。
